## Key Takeaways

### What Went Well

1. **TanStack Query optimistic update pattern** — Story 3.4's `useUpdateTaskStatusMutation` established the pattern (`onMutate` / `onError` / `onSuccess` / `onSettled`, `retry: 0` for destructive ops). This was reused successfully in 3.5 (`useDeleteTaskMutation`) and 3.7 (`useClearCompletedTasksMutation`), reducing rework.

2. **Route ordering discipline** — Stories 3.2 and 3.3 documented the critical constraint: `DELETE /tasks/completed` must be registered before `DELETE /tasks/:id` to avoid `:id` matching the literal `"completed"`. Forward-reference comments and explicit placement prevented regression.

3. **Spy-test placement pattern** — Stories 3.1, 3.2, and 3.3 established that Prisma spy tests (for DB failure simulation) should run **last** in the describe block. This avoids `vi.restoreAllMocks()` / `mockRestore()` leakage affecting subsequent tests.

4. **SwipeableTaskCard extraction** — Story 3.5 extracted card JSX from `HomePage.tsx` into a dedicated component. This improved separation of concerns and made the completed-section collapse (3.6) and clear-all (3.7) changes easier to integrate.

5. **Strong code review culture** — Every story had Senior Developer review. Recurring fixes: UUID validation, `.strict()` on Zod schemas, stronger AC assertions, state cleanup (rollback ID leakage in 3.7), and accurate delete-count reporting in 3.8.

6. **Cron job isolation** — Story 3.8 kept background jobs in `packages/backend/src/jobs/`, wired into `index.ts` with graceful shutdown and failure isolation so HTTP server remains unaffected.

### Challenges & Growth Areas

1. **jsdom / testing environment gaps**
   - **Swipe gesture not unit-testable** (3.5): `TouchEvent` support in jsdom is unreliable. Tests use `data-testid` delete button instead; swipe is validated manually or via E2E.
   - **localStorage in tests** (3.6): jsdom did not provide full Web Storage API (`localStorage.clear` missing). Added in-memory `localStorageMock` with `vi.stubGlobal` to enable AC6 (persist collapse state) tests.

2. **TypeScript strict mode**
   - `sx={undefined}` incompatible with `exactOptionalPropertyTypes` (3.5) — fixed with `sx={}`.
   - `TaskStatus` string literals vs enum in strict mode (3.4) — required importing `TaskStatus` as a value and using `TaskStatus.ACTIVE` / `TaskStatus.COMPLETED`.

3. **Click target and event propagation** (3.4)
   - Tests clicked the parent `<li>`; events don't propagate down to children. Card `onClick` never fired. Fixed by clicking the text element directly so the event bubbles up to the Card.

4. **Rollback state management** (3.7)
   - Code review caught `rollbackFadeTaskIds` leakage across subsequent clear attempts. Fixed by clearing the set at clear start and on success.

### Recurring Review Themes

- **UUID validation** — All `:id` route handlers must validate with `uuidParamSchema`; malformed IDs return 400, not 500.
- **Zod `.strict()`** — Schemas reject extra fields (e.g., client sending `completedAt`) to avoid security/consistency issues.
- **Optimistic timing proof** — Tests use deferred promises to prove UI updates occur *before* server response.
- **Explicit AC assertions** — Reviews demanded direct AC-to-test mapping (e.g., AC5 "task stays deleted" after successful DELETE).
