## Key Takeaways

### What Went Well

1. **Architecture docs as source of truth** — Stories 1-1 through 1-5 consistently referenced `architecture-decisions-*` and `technical-architecture-*` documents. This reduced ambiguity and kept implementations aligned.

2. **Deterministic verification over manual claims** — Story 1-4 used Playwright to objectively verify HMR (176ms update, state preserved). Story 1-5 captured explicit command outputs for Testcontainers and coverage. Code reviews increasingly demanded evidence.

3. **“Previous Story Learnings” sections** — Each story’s Dev Notes included learnings from prior stories (e.g., 1-2 referencing 1-1 pnpm/tsconfig; 1-3 referencing 1-2 Docker context). This improved continuity.

4. **Per-profile database isolation (Story 1-2)** — Using separate database services per profile with dedicated volumes (`postgres_data_local`, `postgres_data_test`, `postgres_data_prod`) gave true environment isolation.

5. **Testcontainers migration-first strategy (Story 1-5)** — Migration-first setup with `prisma db push` fallback for bootstrap states made integration tests deterministic and repeatable.

6. **Code review rigor** — Senior Developer reviews caught tsconfig mismatches, Docker target misconfigurations, and AC alignment gaps. Several HIGH findings were fixed before stories were marked done.

### Challenges & Growth Areas

1. **TypeScript strict mode** — Stories 1-1 and 1-3 had issues with `exactOptionalPropertyTypes`, Pino logger typing, and Zod `.url()` rejecting `postgresql://`. Patterns that helped: split dev/prod config objects, avoid `undefined` in optional props.

2. **Docker monorepo context** — Story 1-2 clarified that build context must be project root (`.`), not `packages/backend`, for `workspace:*` resolution. `tsconfig.base.json` needed to be copied into the image.

3. **AC4 hot-reload evidence (Story 1-3)** — Automated evidence for “&lt;2s restart” was hard to produce in the execution environment. Manual verification was accepted after attempts to automate.

4. **AC alignment in code reviews** — Multiple stories had mismatches between AC wording and implementation (e.g., shared vs per-profile DB, test stage behavior). Strengthening AC review before dev reduced rework.

### Recurring Review Themes

- **AC evidence** — Reviews requested objective proof (commands, outputs, screenshots) instead of “verified manually.”
- **File list accuracy** — Story File List was out of sync with actual changes in several stories; alignment was improved over the epic.
- **Docker production targets** — `backend-prod` initially used `development` target; corrected to `production` with proper `tsc` output.
